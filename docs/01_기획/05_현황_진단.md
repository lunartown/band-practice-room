# 현황 진단

> 작성일: 2026-08-30
> 상태: 초안
> 근거: PostHog(2026-07-13~08-30), GA4(2026-08-10~), prod DB, 배포 산출물 직접 확인

밴드룸 재조사([04_경쟁사_분석.md](04_경쟁사_분석.md)) 과정에서 우리 쪽 지표를 함께 확인했다. 이 문서는 그 결과를 각도별로 정리한다.

## 1. 먼저 — 지금 판단할 수 있는 것과 없는 것

**광고는 2026-08-29에 시작했다.** 전체 사용자 165명 중 **97명이 8/29에, 5명이 8/30에 처음 들어왔다(62%).**

이 사실이 해석을 크게 제약한다.

| 항목 | 지금 판단 가능한가 | 이유 |
| --- | --- | --- |
| 발견(SEO·AEO) | **가능** | 배포 산출물을 직접 확인한 구조적 사실. 트래픽 양과 무관하다 |
| 데이터 품질 | **가능** | DB 조회 결과 |
| 앱 | **가능** | 구조적 사실 |
| 제품 결함 | **가능** | 화면을 직접 확인 |
| 전환 | **잠정** | 원인은 좁혀졌으나 신버전 표본이 9명뿐 |
| 리텐션 | **불가** | 62%가 이틀 안에 들어와 재방문할 시간이 없었다 |

특히 "154명이 하루만 방문(93%)"은 리텐션이 아니라 코호트 나이를 잰 수치다. 어제 처음 온 97명은 재방문 기회가 아직 없었다. **리텐션은 8/29 코호트가 2주쯤 지난 뒤에야 의미가 생긴다. 그 전까지는 문제 목록에서 뺀다.**

## 2. 발견 — 가장 큰 문제

7주간(7/13~08/30) `app_open` 405회의 유입원:

| 유입 | 횟수 |
| --- | --- |
| 직접 | 290 |
| 인스타그램 | 68 |
| 페이스북 | 41 |
| 구글 | 3 |
| 빙 | 3 |
| AI 엔진(chatgpt·perplexity 등) | 0 |

GA4 최근 28일도 190세션 중 Organic Search 7세션이다.

원인은 두 겹이다.

1. **색인할 페이지가 없다.** `sitemap.xml`의 URL이 1개고, 그 1개도 본문 없는 2.5KB SPA 셸이다. "합정 합주실", "강남 합주실 가격" 같은 검색어에 대응할 페이지가 존재하지 않는다.
2. **크롤러가 볼 내용이 없다.** LLM 크롤러(GPTBot, PerplexityBot, ClaudeBot)는 대부분 JS를 실행하지 않는다. 241개 합주실 데이터를 보유하고도 기계가 읽을 수 없는 형태로 두고 있다. AEO 유입 0건은 이 결과다.

밴드룸은 같은 시장에서 232개 URL을 색인 가능한 상태로 두고 있다.

부수적으로 **표기 이름과 검색 이름이 어긋나 있다.** 배포된 `<title>`, `og:site_name`은 전부 일반명사 "합주실"이고, 검색으로 찾을 수 있는 "합주실닷컴"은 공유 시트(`lib/share.ts`)와 관리자 화면에만 있다. 사용자가 브랜드명을 학습할 접점이 사실상 없다.

## 3. 전환 — 오픈 화면이 원인, 잠정 해결

| 날짜 | 방문 | 결과 도달 | 예약 클릭 |
| --- | --- | --- | --- |
| 8/28 | 3 | 2 | 1 |
| **8/29 (광고 시작, 구버전)** | **101** | **22 (22%)** | **10** |
| **8/30 (오픈 화면 제거)** | **9** | **8 (89%)** | **2** |

8/29 유입 101명은 전원 오픈 화면이 있는 구버전을 봤다. 유입원별 도달률은 인스타 54명 중 10명(19%), m.facebook 27명 중 3명(11%), 직접 13명 중 7명(54%)이다.

**속도는 원인이 아니었다.** LCP p50 0.85초, 첫 결과 도달까지 p50 2.2초 / p90 6.3초다. `results_shown`은 `loading`이 끝나야 발화하므로 로딩 지연이면 미발화로 나타나는데, 도달 실패 세션은 `app_open` 외 이벤트가 없다.

배포 배경과 기준선은 [docs/배움/01_오픈화면_제거.md](../배움/01_오픈화면_제거.md)에 있다. **8/30 표본이 9명이고 반나절치라 확정이 아니다.**

## 4. 제품

- **결과의 시간 표현이 얕다.** `15~22시` 같은 범위 칩 하나여서 중간 공백을 표현하지 못한다. 밴드룸의 룸별 24시간 타임라인이 이 점에서 낫다.
- **가격·인원 필터가 없다.**
- **데스크톱에서 화면 낭비가 크다.** 넓은 화면에서 가운데 폰 너비만 쓰고 양옆이 빈다.

## 5. 데이터 품질

| 항목 | 상태 |
| --- | --- |
| 활성 룸 | 485개 |
| 가격 없음 | 121개 (25%) |
| **인원 없음** | **334개 (69%)** |
| 슬롯 없는 활성 스튜디오 | 39개 |
| 이미지 없음 | 0개 |
| 미래 슬롯 | 263,329건 (2026-09-28까지) |

인원이 69% 비어 있어 인원 필터를 만들 수 없다. 슬롯이 없는 활성 스튜디오 39개는 목록에는 뜨지만 시간이 나오지 않는 상태일 수 있고, 아래 "결과 없음" 문제와 연결될 가능성이 있다.

## 6. 앱

PostHog 호스트 기준 `hapjusil.com` 155명, 네이티브 앱으로 보이는 `localhost` 2명이다. GA4도 앱 스트림 데이터가 0이고 웹 스트림만 186세션이다. **실사용 흔적이 사실상 없다.**

안드로이드는 Play 비공개 테스트 요건(테스터 확보)에 막혀 아직 출시하지 못했다. 웹에는 앱을 알리는 장치가 전혀 없다 — `index.html`에 `apple-itunes-app` 메타가 없고, 앱스토어 링크도 어디에도 없다. **공유 링크를 받은 사람은 앱의 존재를 알 수 없다.**

대응 방향은 [06_유통_전략.md](06_유통_전략.md) 4절에 정리했다.

## 7. 사업

수익 경로가 없다. 광고비는 나가는데 회수 구조가 없고 유입은 광고에 의존한다. 밴드룸은 통신판매업 신고와 입점 모델까지 문서로 그려두었다.

## 8. 미해결

- **8/20에 직접 유입 16명이 들어와 결과 도달 0명이다.** prod 트래픽이고 광고 이전이다. 봇인지 그날 배포 문제인지 확인하지 못했다.
- **결과 도달 세션 82개 중 23개(28%)가 "결과 없음" 화면을 한 번 이상 봤다.** 오픈 화면과 무관한 별개 문제다. 조건 완화 유도가 작동하는지 확인이 필요하다.
- **GA4 앱 스트림에 데이터가 없다.** 앱 실사용이 없어서인지 계측이 안 붙어서인지 구분하지 못했다.
