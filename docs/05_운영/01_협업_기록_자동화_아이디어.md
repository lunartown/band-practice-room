# 협업 기록·자동화 아이디어

> 작성일: 2026-08-30  
> 상태: 대화에서 나온 아이디어 초안. 도구와 운영 방식은 미결정

## 배경

지금까지는 개발 데이터, 의사결정의 근거와 의도, 운영 데이터를 저장소와 CLI에서 함께 확인하며 사람 한 명과 AI가 작업했다. 이 방식은 서로의 맥락이 자연스럽게 연결된다는 장점이 있었다.

광고 운영을 시작하고 프로덕트 디자이너가 협업에 참여하면서 다음 문제가 생겼다.

- 광고 시작일처럼 기본적인 운영 사건이 기록되지 않으면 AI가 현재 상황을 잘못 전제할 수 있다.
- UI 개선, Figma 화면 피드백, 광고 소재 피드백, 성과를 보고 내린 결정이 여러 대화와 도구에 흩어진다.
- 팀원은 Markdown이나 GitHub에 익숙하지 않으므로 저장소만을 정본으로 삼으면 기록과 열람의 부담이 커진다.
- AI와 나눈 유용한 대화와 제안도 팀원이 읽고 이후 의사결정에 활용할 수 있으면 좋겠다.

## 원하는 상태

사람은 Figma, Notion처럼 익숙한 화면에서 읽고 기록하고, AI는 같은 내용을 저장소나 API를 통해 조회할 수 있게 한다. 한쪽이 다른 쪽의 도구 사용법을 모두 익혀야 하는 구조는 피한다.

우선 기록할 대상은 다음 네 종류로 단순화할 수 있다.

| 종류 | 예시 |
| --- | --- |
| 사건 | 광고 시작·중단, 소재 교체, 배포 |
| 관측 | 광고 성과 변화, 사용자 반응, 발견한 문제 |
| 결정 | 무엇을 하기로 했는지와 그 이유 |
| 작업 | 담당자, 기한, 현재 상태 |

## 운영 방식 후보

아직 확정하지 않았지만 다음과 같은 흐름을 검토할 수 있다.

1. 팀원이 Notion의 간단한 양식이나 버튼으로 사건·관측·결정·작업을 기록한다.
2. 자동화가 새 기록을 저장소의 구조화된 문서나 AI가 읽을 수 있는 데이터로 동기화한다.
3. AI 대화에서 공유할 가치가 있는 내용은 사람이 명령하거나 버튼을 누르면 팀 공유본으로 변환해 Notion에 올린다.
4. Figma 작업은 결과물 전체를 복제하기보다 관련 화면 링크, 피드백 요약, 결정과 근거를 기록한다.
5. 광고 데이터는 수치 자체와 그 수치를 보고 내린 해석·결정을 연결해서 남긴다.

핵심은 모든 도구를 완전히 양방향 동기화하는 것이 아니라, 사람이 부담 없이 기록하면 AI도 같은 맥락을 읽을 수 있는 최소 연결을 만드는 것이다.

## 관련 자동화 아이디어

합주실 관련 메일이 도착하면 AI가 저장소의 맥락과 공식 자료를 확인하여 다음 내용을 제안하는 자동화도 아이디어로 나왔다.

- 조치 필요 여부와 긴급도
- 기한과 방치했을 때의 위험
- 확인한 근거
- 추천 조치
- 필요한 경우 회신 초안

Claude Code Cloud Routine의 API 트리거와 저장소 스킬을 조합하면 로컬 컴퓨터를 계속 켜두지 않고도 실행할 수 있다. 단, 외부 메일 발송이나 광고·운영 설정 변경은 초기에는 자동 실행하지 않고 사람의 승인을 받는 방향이 안전하다.

## 열린 질문

- 팀원이 실제로 가장 편하게 기록할 화면은 Notion인지, 별도의 간단한 입력 화면인지
- 정본을 Notion으로 둘지, 저장소로 둘지, 또는 정보 종류별로 나눌지
- AI 대화는 전문을 보관할지, 결정과 근거만 추출해 보관할지
- 광고 데이터와 회의·결정 기록을 어떤 식별자로 연결할지
- 자동 동기화와 사람이 누르는 명시적 동기화 중 어느 쪽이 오류를 발견하고 수정하기 쉬운지

이 문서는 구현 계획이 아니라, 운영과 협업의 맥락을 팀과 AI가 함께 공유하기 위한 시스템이 필요하다는 문제의식과 아이디어를 잊지 않기 위한 기록이다.
