# 계측 조회

이벤트를 어디에 심는지는 [`src/web/src/lib/analytics.ts`](../../src/web/src/lib/analytics.ts) 주석이 원천이다.
이 문서는 **쌓인 데이터를 어떻게 꺼내 보는가**만 다룬다.

## 도구 네 가지

| 도구 | 용도 | 조회 가능 |
| --- | --- | --- |
| PostHog | 자체 분석 + 세션 리플레이 | HogQL API, 웹 대시보드 |
| GA4 | 지표·유입 채널 | Data API, 웹 대시보드 |
| Meta Pixel | 광고 성과를 Meta에 회신 | Meta 광고 관리자 |
| Vercel Analytics | 페이지 단위 트래픽 | Vercel 대시보드 |

자격증명은 모두 `_local/`에 있다. 이 디렉터리는 `.gitignore`에서 통째로 제외되므로 커밋되지 않는다.
셸에서 쓸 때는 `set -a; source _local/ops.env; set +a`를 실행한다.

같은 이벤트를 PostHog와 GA4에 동시에 보낸다. 두 수치가 다르면 대개 **수집 시작일 차이**(GA4는 2026-08-10부터, PostHog는 2026-07-13부터)이거나 GA4의 자동 이벤트(`session_start`, `first_visit`) 때문이다.

## GA4

- 속성: `properties/543520889` (계정 `396957528` "Default Account for Firebase")
- 웹 스트림 측정 ID: `G-Z67TH01T05` / 앱 스트림: `com.hapjusil.app` (iOS·Android)

조회 권한은 전용 서비스 계정 `_local/ga4-admin-sa.json`(`ga4-admin@hapjusil.iam.gserviceaccount.com`)에 있다.
개인 gcloud 계정은 스코프가 부족해 403이 난다.

```python
from google.oauth2 import service_account
import google.auth.transport.requests, urllib.request, json

c = service_account.Credentials.from_service_account_file(
    '_local/ga4-admin-sa.json',
    scopes=['https://www.googleapis.com/auth/analytics.readonly'])
c.refresh(google.auth.transport.requests.Request())

req = urllib.request.Request(
    'https://analyticsdata.googleapis.com/v1beta/properties/543520889:runReport',
    data=json.dumps({"dateRanges": [{"startDate": "30daysAgo", "endDate": "today"}],
                     "dimensions": [{"name": "eventName"}],
                     "metrics": [{"name": "eventCount"}, {"name": "totalUsers"}]}).encode(),
    headers={'Authorization': 'Bearer ' + c.token, 'Content-Type': 'application/json'})
print(json.load(urllib.request.urlopen(req)))
```

메타데이터는 Admin API(`analyticsadmin.googleapis.com/v1beta/properties/543520889/...`)의
`dataStreams`, `customDimensions`, `customMetrics`로 확인한다.

주의할 점:

- `analyticsdata.googleapis.com`이 GCP 프로젝트 `hapjusil`에 **활성화돼 있어야 한다**. 2026-08-30에 활성화했다.
- 커스텀 파라미터는 GA4에 **등록해야** 조회된다. 문자열은 `customEvent:<param>`, 숫자는 `customMetric:<param>`으로 참조한다. 등록 이전 데이터는 `(not set)`으로 남는다.
- 유입 채널에 자체 공유 링크가 소스로 섞여 들어온다(`room`, `studio`). 광고 성과를 볼 때는 UTM이 붙은 것만 봐야 한다.

## PostHog

- 프로젝트 `510060` (US 클라우드)
- 리플레이 목록: `https://us.posthog.com/project/510060/replay`
- 개별 리플레이: `https://us.posthog.com/project/510060/replay/<session_id>`

조회에는 **개인 API 키**(`phx_...`)가 필요하다. 클라이언트에 심는 `phc_...`는 전송 전용이라 조회 권한이 없다.
키는 `_local/ops.env`에 `POSTHOG_PERSONAL_API_KEY`로 들어 있다(발급: PostHog → Settings → Personal API keys).

```bash
set -a; source _local/ops.env; set +a

curl -s -H "Authorization: Bearer $POSTHOG_PERSONAL_API_KEY" -H "Content-Type: application/json" \
  -X POST "https://us.posthog.com/api/projects/510060/query/" \
  -d '{"query":{"kind":"HogQLQuery","query":"select event, count() from events group by event order by 2 desc"}}'
```

HogQL에서 걸리기 쉬운 것들:

- **한글 별칭을 못 쓴다.** `as 이벤트`는 문법 오류가 난다. 별칭은 ASCII로 쓰고 표시할 때 한글을 붙인다.
- 성공 응답에도 `"error": null` 키가 들어 있다. `'error' in d`로 판정하면 전부 실패로 보인다. 값의 참/거짓으로 판정해야 한다.
- 세션 ID는 `properties.$session_id`다. `events.session_id` 컬럼은 없다.
- 리플레이 테이블 `raw_session_replay_events`에는 `duration`이나 `start_time`이 없다. `min_first_timestamp`, `max_last_timestamp`를 쓴다.
- 집계 함수 안에 집계 결과를 다시 넣을 수 없다. 사용자 단위 퍼널은 서브쿼리로 사람별 집계를 만든 뒤 바깥에서 세는 2단 구조로 쓴다.

사용자 단위 퍼널 예시:

```sql
select
  countIf(event='app_open')      as opened,
  countIf(event='results_shown') as saw_results,
  countIf(event='booking_click') as booked
from (select person_id, event from events group by person_id, event)
```

## 리플레이에서 보이는 것

입력값은 전부 마스킹된다(`maskAllInputs: true`). 검색어 같은 텍스트는 가려지고, 클릭·스크롤·화면 전환은 그대로 보인다.
